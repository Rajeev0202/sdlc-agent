# GitHub Integration Guide

This document describes how to enable real GitHub integration for the SDLC Agent, allowing it to create pull requests and post review comments directly to GitHub.

## Overview

The SDLC Agent supports two modes for GitHub operations:

1. **Mock Mode (Default)**: Uses an in-memory mock client for testing and demos
2. **Real GitHub Mode**: Uses GitHub REST API to create actual PRs and post review comments

## Prerequisites

To use real GitHub integration, you need:

1. **GitHub Personal Access Token** with the following permissions:
   - `repo` (Full control of private repositories)
   - `pull_requests` (Read/Write access to pull requests)

2. **Git configured** with the repository remote pointing to GitHub

## Setup

### 1. Generate GitHub Personal Access Token

1. Go to GitHub Settings → Developer settings → Personal access tokens → Tokens (classic)
2. Click "Generate new token (classic)"
3. Give it a descriptive name (e.g., "SDLC Agent")
4. Select the following scopes:
   - ✅ `repo` (all sub-permissions)
   - ✅ `workflow` (if you want to trigger workflows)
5. Click "Generate token"
6. **Copy the token** (you won't see it again!)

### 2. Configure Environment Variables

Set the GitHub token in your environment:

**Windows (PowerShell):**
```powershell
$env:GITHUB_TOKEN = "ghp_your_token_here"
```

**Windows (Command Prompt):**
```cmd
set GITHUB_TOKEN=ghp_your_token_here
```

**Linux/Mac:**
```bash
export GITHUB_TOKEN=ghp_your_token_here
```

**Persistent Configuration (.env file):**
```bash
# Create .env file in project root
GITHUB_TOKEN=ghp_your_token_here
POST_REVIEW_COMMENTS=true
```

### 3. Optional: Configure Review Comments

By default, when `GITHUB_TOKEN` is set, the agent will post review comments. To control this:

```bash
# Disable review comments (only create PRs)
POST_REVIEW_COMMENTS=false

# Enable review comments (default when GITHUB_TOKEN is present)
POST_REVIEW_COMMENTS=true
```

## Usage

Once configured, the SDLC pipeline will automatically use real GitHub integration:

### Stage 3 - Code Generation & PR Creation

```bash
# Run the full pipeline
python -m sdlc_agent.cli run samples/brd_natwest_card_freeze.md
```

**What happens:**
1. Generates code based on approved stories
2. Commits changes to a feature branch
3. Pushes branch to GitHub
4. **Creates a draft PR** with:
   - Proper title from story
   - Description with story links
   - List of changed files
   - "Generated by SDLC Agent" footer

### Stage 4 - Code Review & Comments

**What happens:**
1. Reviews the code for security, standards, and logic issues
2. **Posts inline comments** on specific lines with issues
3. **Posts a summary comment** with:
   - Overall verdict (PASS/FAIL)
   - Findings grouped by severity
   - Findings grouped by category
   - List of blocking issues

**Key Point:** Code is written, committed, and pushed to GitHub BEFORE the PR is created. This ensures the PR has actual code to review.

### GitHubRestClient API

The client uses GitHub REST API v3:

| Method | Endpoint | Purpose |
|--------|----------|---------|
| `POST /repos/{owner}/{repo}/pulls` | Create PR | Creates draft pull request |
| `POST /repos/{owner}/{repo}/pulls/{pr}/reviews` | Post Review | Posts review with inline comments |
| `POST /repos/{owner}/{repo}/issues/{pr}/comments` | Post Comment | Posts general PR comments |
| `PATCH /repos/{owner}/{repo}/pulls/{pr}` | Update PR | Marks PR ready for review |
| `POST /repos/{owner}/{repo}/issues/{pr}/labels` | Add Labels | Adds labels to PR |

## Configuration Reference

### Environment Variables

| Variable | Required | Default | Description |
|----------|----------|---------|-------------|
| `GITHUB_TOKEN` | Yes (for real mode) | - | GitHub personal access token |
| `POST_REVIEW_COMMENTS` | No | `true` | Whether to post review comments |

### Code Configuration

```python
from sdlc_agent.integrations import GitHubRestClient

# Initialize with explicit token
github = GitHubRestClient(
    repo="owner/repo",  # Optional: auto-detected from git remote
    token="ghp_xxx"      # Optional: read from GITHUB_TOKEN env var
)

# Create PR
pr = github.open_pull_request(
    branch="feature/my-feature",
    title="feat: Add new feature",
    body="Implementation of user story US-123",
    files=[...],
    story_ids=["US-123"]
)

# Post review comments
github.post_review_comments(pr_number=42, review_report=report)

# Mark PR ready for review
github.mark_ready_for_review(pr_number=42)

# Add labels
github.add_labels(pr_number=42, labels=["enhancement", "needs-review"])
```

## Troubleshooting

### Error: "GitHub token required"

**Cause**: `GITHUB_TOKEN` environment variable is not set.

**Solution**:
```bash
export GITHUB_TOKEN=ghp_your_token_here
```

### Error: "GitHub API error: 401"

**Cause**: Invalid or expired GitHub token.

**Solution**: Generate a new token with the correct permissions.

### Error: "GitHub API error: 403"

**Cause**: Token doesn't have required permissions.

**Solution**: Ensure token has `repo` and `pull_requests` scopes.

### Error: "GitHub API error: 404"

**Cause**: Repository not found or token doesn't have access.

**Solution**: 
- Verify repository name is correct
- Ensure token has access to the repository
- For private repos, ensure `repo` scope is enabled

### Error: "Could not determine repository from git remote"

**Cause**: Git remote is not configured or doesn't point to GitHub.

**Solution**:
```bash
git remote add origin https://github.com/owner/repo.git
# or
git remote set-url origin https://github.com/owner/repo.git
```

### Review comments not appearing

**Cause**: Comments may fail if:
- File path doesn't exist in the PR
- Line number is invalid
- PR is already merged

**Solution**: Check logs for specific error messages. The client will fall back to general comments if inline comments fail.

## Security Best Practices

1. **Never commit tokens to git**
   - Use `.env` files (add to `.gitignore`)
   - Use environment variables
   - Use secret management systems in CI/CD

2. **Use fine-grained tokens when possible**
   - Limit to specific repositories
   - Set expiration dates
   - Revoke tokens when no longer needed

3. **Rotate tokens regularly**
   - Set calendar reminders
   - Update in all environments

4. **Monitor token usage**
   - Review token activity in GitHub settings
   - Revoke suspicious tokens immediately

## CI/CD Integration

### GitHub Actions

```yaml
name: SDLC Pipeline

on:
  workflow_dispatch:
    inputs:
      brd_path:
        description: 'Path to BRD file'
        required: true

jobs:
  sdlc:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      
      - name: Run SDLC Pipeline
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
        run: |
          python -m sdlc_agent.cli run ${{ github.event.inputs.brd_path }}
```

### Azure DevOps

```yaml
trigger: none

pool:
  vmImage: 'ubuntu-latest'

variables:
- group: sdlc-secrets  # Contains GITHUB_TOKEN

steps:
- task: UsePythonVersion@0
  inputs:
    versionSpec: '3.11'

- script: |
    pip install -r requirements.txt
    python -m sdlc_agent.cli run samples/brd_natwest_card_freeze.md
  env:
    GITHUB_TOKEN: $(GITHUB_TOKEN)
    ANTHROPIC_API_KEY: $(ANTHROPIC_API_KEY)
  displayName: 'Run SDLC Pipeline'
```

## Limitations

1. **Rate Limits**: GitHub API has rate limits (5,000 requests/hour for authenticated requests)
2. **Review Comments**: Can only post on lines that exist in the PR diff
3. **Draft PRs**: Some organizations may restrict draft PR creation
4. **Branch Protection**: May need to bypass branch protection rules for automation
