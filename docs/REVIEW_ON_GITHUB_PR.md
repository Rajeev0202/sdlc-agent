# Code Review on GitHub PR - Complete Flow

## Your Question

> "Will the Review stage happen in the created PR?"

**Answer:** Yes! When using real GitHub integration (with `GITHUB_TOKEN`), Stage 4:
1. ✅ Fetches the actual files from the GitHub PR
2. ✅ Reviews those files (not in-memory copies)
3. ✅ Posts review comments directly on the GitHub PR
4. ✅ Posts inline comments on specific code lines
5. ✅ Posts a summary comment with the verdict

## Complete Flow

### Stage 3: Code Generation & PR Creation

```
1. Generate code
2. Create git branch
3. Write files to disk
4. git commit
5. git push to GitHub
6. Create GitHub PR #42 ────┐
                             │
                             ▼
                   GitHub PR #42 Created
                   - Branch: feature/xyz
                   - Files: src/module.py
                   - Status: Draft
```

### Stage 4: Review on GitHub PR

```
                   GitHub PR #42
                             │
                             ▼
Stage 4: Fetch Files from PR #42
         │
         ├─ GET /repos/owner/repo/pulls/42/files
         │  └─ Returns: list of changed files
         │
         ├─ GET <raw_url> for each file
         │  └─ Returns: actual file content from PR
         │
         ▼
    Review Actual PR Files
         │
         ├─ Security scan
         ├─ Standards check
         ├─ Logic review
         └─ Coverage analysis
         │
         ▼
    Post Review to GitHub PR #42
         │
         ├─ POST /repos/owner/repo/pulls/42/reviews
         │  └─ Inline comments on code lines
         │
         └─ POST /repos/owner/repo/issues/42/comments
            └─ Summary comment with verdict
```

## What Gets Reviewed

### With GITHUB_TOKEN (Real Mode)

```python
# Stage 4 calls:
files = github.get_pr_files(pr.number)
# This fetches:
# - Actual files from the GitHub PR
# - At the current HEAD commit
# - With real content from GitHub's servers

# Then reviews those files:
for file in files:
    findings = scan_file(file.path, file.contents)  # ← Real GitHub content

# Then posts back to GitHub:
github.post_review_comments(pr.number, report)
```

### Without GITHUB_TOKEN (Mock Mode)

```python
# Stage 4 uses:
files = pr.files  # ← In-memory files from Stage 3

# Reviews local committed files:
for file in files:
    findings = scan_file(file.path, file.contents)  # ← Local content

# No posting to GitHub (mock mode)
```

## Code Implementation

### GitHubRestClient.get_pr_files()

```python
def get_pr_files(self, pr_number: int) -> list[CodeFile]:
    """Fetch the actual files from a GitHub PR."""
    
    # 1. Get list of changed files
    files_data = self._make_request(
        "GET",
        f"/repos/{owner}/{repo}/pulls/{pr_number}/files"
    )
    
    # 2. Fetch content for each file
    code_files = []
    for file_info in files_data:
        # Fetch from raw_url
        response = requests.get(
            file_info["raw_url"],
            headers={"Authorization": f"token {self.token}"}
        )
        contents = response.text
        
        code_files.append(
            CodeFile(
                path=file_info["filename"],
                language=detect_language(file_info["filename"]),
                contents=contents  # ← Actual content from GitHub
            )
        )
    
    return code_files
```

### Stage 4: Review with GitHub Files

```python
def run(pr, *, claude, github, post_comments):
    # Fetch actual files from GitHub PR
    if github and isinstance(github, GitHubRestClient):
        files_to_review = github.get_pr_files(pr.number)
        print("Review source: GitHub PR")
    else:
        files_to_review = pr.files  # Use local files
        print("Review source: Local files")
    
    # Review the files
    findings = []
    for file in files_to_review:
        findings.extend(scan_file(file.path, file.contents))
    
    # Post comments to GitHub
    if post_comments and github:
        github.post_review_comments(pr.number, report)
```

## Advantages of Reviewing on GitHub PR

### 1. Reviews Actual PR State

- ✅ Reviews what's actually in the PR
- ✅ Not dependent on local state
- ✅ Reflects any manual changes to the PR

### 2. Comments Visible to Team

- ✅ Comments appear on GitHub
- ✅ Team members can see findings
- ✅ Integrated with GitHub notifications
- ✅ Can reply to comments

### 3. PR Workflow Integration

- ✅ Comments block merge if needed
- ✅ Can request changes
- ✅ Can approve when fixed
- ✅ Integrates with GitHub Actions

### 4. Audit Trail

- ✅ Review history preserved
- ✅ Can see when issues were found
- ✅ Can track resolution
- ✅ Part of PR timeline

## Comparison: Local vs GitHub Review

| Aspect | Local Review | GitHub PR Review |
|--------|--------------|------------------|
| **Source** | In-memory files | Fetched from GitHub |
| **Accuracy** | May be stale | Always current PR state |
| **Visibility** | Only in logs | Visible on GitHub |
| **Collaboration** | Not shareable | Team can see/reply |
| **Audit** | Only in logs | Part of PR history |
| **Integration** | None | GitHub Actions, checks |

## Troubleshooting

### Issue: "No files fetched from GitHub"

**Causes:**
- PR doesn't exist yet
- Network issues
- Invalid GITHUB_TOKEN
- PR has no changed files

**Solution:**
- Verify PR was created in Stage 3
- Check token permissions
- Check network connectivity

### Issue: "Comments not appearing on GitHub"

**Causes:**
- `post_comments=False`
- `POST_REVIEW_COMMENTS=false` in env
- GitHub API error
- Insufficient token permissions

**Solution:**
- Set `POST_REVIEW_COMMENTS=true`
- Check token has `repo` scope
- Check logs for API errors

### Issue: "Reviewing wrong files"

**Causes:**
- Fetching failed, fell back to local
- PR was updated after Stage 3
- Commit SHA mismatch

**Solution:**
- Check logs for "Fetched X files from GitHub"
- Verify PR state on GitHub
- Re-run if PR was manually updated
